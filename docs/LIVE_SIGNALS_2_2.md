# LITTLE PARK 2.2 — 실제 데이터와 시연의 분리

## 이번 변경

SKT 실데이터 연결은 완료되지 않았습니다. 기존 2.1 게임풍 지도는 유지하고, 실제 외부 기상예보와 인증된 현장 관찰 입력을 추가했습니다. 기본 화면은 인원 미관측 상태를 그대로 표시합니다. 임의의 624명이나 도민 23%를 실제 현장 정보처럼 사용하지 않습니다.

- 기본 화면: `/` — 관찰된 구역만 표시, 미관측 인원·도민·관광객은 빈 상태.
- 현장 입력: `/observe` — 현재 Render의 `INGEST_TOKEN`으로 인증. 실제 관찰한 시각·구역·혼잡 등급 또는 인원·대기시간을 입력합니다.
- 가상 시연: `/?demo=1` — 624명의 고정 가상 데이터. 실제 관측이 아님을 명시합니다. 실제 데이터 저장소에는 쓰지 않습니다.
- 신호 API: `/api/v1/parks/981/signals` — 기상예보 출처·발표시각·예보대상시각, 유효한 현장 입력, SKT 연결상태.
- 기존 `/health`, `/live`, `/stream` 경로는 유지합니다. `/health`의 버전은 `live-signals-2.2.0`입니다.

## 실제 데이터의 의미

기상정보는 MET Norway의 좌표 기반 수치예보입니다. 파크 현장 기상관측, 실제 레이스 운영 여부, 인원 측정값이 아닙니다. 기온·바람·강수량으로 파크 인원을 만들어내지 않습니다. 발표시각·단위·좌표·유효시각을 검사합니다. 원천 발표시각이 18시간 이상 오래됐거나 현재 예보 구간이 없으면 사용하지 않습니다.

현장 입력은 입력자가 확인했다고 선언한 관찰값이며 독립적으로 검증된 센서 데이터가 아닙니다. 사람 수와 주차 차량 수는 별도입니다. 특정 구역 관찰값을 전체 파크 인원으로 확대하지 않습니다. 통신 집계의 전체 수치를 실내 시설별로 자동 배분하지 않습니다. 도민·관광객 정보가 없으면 빈 값으로 남깁니다.

관찰값은 원래 관찰시각부터 15분 후 만료됩니다. 재전송만으로 수명이 늘어나지 않습니다. 현재 저장 방식은 메모리이므로 서버 재시작 때 사라집니다. 사용자 이름·전화번호·위치 추적·영상은 수집하지 않습니다. 장기 운영용 이력 저장과 검증 모델은 별도 작업입니다.

## 현장 입력 사용법

1. `/observe`에 접속합니다.
2. 비밀키 입력란에 Render의 기존 `INGEST_TOKEN` 값을 직접 입력합니다. 키를 채팅·GitHub·공개 화면에 공유하지 마세요. 예전에 예시로 공유한 키를 사용했다면 Render에서 새로 생성하세요.
3. 실제 확인한 구역과 시각을 선택합니다. `파크 전체`는 전체 인원을 실제로 확인했을 때만 사용합니다.
4. 확인한 항목만 입력합니다. 혼잡 등급 하나만 입력해도 됩니다. 인원을 모르면 비워두세요.
5. 실제 현장 관찰 확인란을 체크한 뒤 전송합니다.
6. 기본 지도에서 해당 구역만 갱신되는지 확인합니다. 키는 브라우저 저장소나 URL에 저장하지 않습니다. 입력 완료 후 `키 지우기`를 누릅니다.

새 관찰은 기존 관찰보다 나중 시각이어야 합니다. 공개 API는 인증 없는 입력을 거절하며, 값 검증·크기 제한·빈도 제한을 적용합니다. 테스트용 입력은 로컬 테스트에만 사용했으며 운영 사이트에 전송하지 않았습니다.

## SKT 연결 상태와 다음 조건

공식 SK open API 요금표에서 장소 혼잡도 체험 호출은 하루 3건으로 확인했습니다. 이것만으로 5분마다 수집하는 서비스는 구성할 수 없습니다. 현재 서비스의 인증키와 9.81파크 POI 제공 여부는 확보되지 않았습니다. 유료 API 신청이나 과금 호출을 실행하지 않았습니다.

공사/제공기관이 승인한 집계 피드가 확보되면 아래 계약으로 기존 입력 API를 사용할 수 있습니다. 단순 밀도·일별 방문자·주변 지역 유동인구를 파크 현재 인원으로 표시하면 안 됩니다.

필수 필드: `source=JTO_SKT_REALTIME` 또는 `SKT_REALTIME`, `scopeType=park-boundary`, `metric=instantaneous-population`, 승인된 `scopeId`, 시간대가 포함된 `observedAt`, 정수형 `people.total`. 도민·관광객 값은 선택이며, 둘 다 있으면 합이 전체와 일치해야 합니다.

Render 환경변수:
- `JTO_APPROVED_SCOPE_ID`: 실제 제공기관이 확인한 파크 집계구역 ID.
- `INGEST_TOKEN`: 인증 전송용 기존 비밀키.
- 자동 pull을 사용할 때만 `DATA_MODE=auto`, `JTO_SKT_API_URL`, 필요 시 `JTO_SKT_API_TOKEN`.
- 기존 `DATA_MODE=estimated`는 JTO 자동 pull을 끕니다. 기상예보와 현장 관찰 기능은 별도로 동작합니다.
- `WEATHER_ENABLED=false`로 기상 외부 요청을 끌 수 있습니다.

현재 어댑터는 이 명시적 JSON 계약을 처리합니다. 임의의 SK open API URL·키·POI를 추측하지 않으며, 로그인·인증서 검증을 우회하지 않습니다. 인증서와 스키마가 확인된 원천 피드를 확보한 후 실제 수신 검증이 필요합니다.

## 실행과 검증

Node 22에서 `npm start`. 시작 시 기존 지도 원본을 검증하고 새 통합 화면을 생성합니다. `server-v22.mjs`가 실행되며, 기존 서버 파일은 참고용으로만 남습니다. 정적 파일 제공은 화면 관련 파일로 제한합니다. `.env`, 원천 데이터, 서버 코드를 웹으로 제공하지 않습니다.

`npm test`: 서버/정규화/만료/인증/부분 관찰/기상 스키마/HTTPS 입력 등을 검사하는 28개 테스트.

별도 오프라인 브라우저 테스트 10개: 지도 상호작용, 모바일 폭, 미관측 표시, 구역별 갱신, 입력 화면 등. 브라우저의 fetch/SSE는 모의 응답으로 검사했으며, 실제 서버 HTTP 검사는 Node 테스트로 분리했습니다. 이는 현장 정확도 시험이 아닙니다.

`.github/workflows/verify-live-signals.yml`는 이 코드에 대해 테스트 후 배포 버전·정적 파일 해시·공개 API를 읽기 전용으로 확인합니다. 실제 배포 확인 결과는 해당 실행 로그/산출물이 기준이며, 본 문서만으로 배포 완료를 주장하지 않습니다.

정확도 API는 검증 전인 동안 `validated:false`, `accuracy:null`을 반환합니다. 80%·90%는 목표일 뿐 달성 수치가 아닙니다.
